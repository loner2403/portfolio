# V3.3 "One Page" design plan

Branch `feat/v3-awwwards-pass`. Builds on the V3.2 "Stacked" addendum in `docs/V3-CONTROL-ROOM.md` (warm palette, serif name lockup, sticky colour cards, clip-path wipes). Status: APPROVED and built 2026-10-19 (C0-C9, Haiku implementer, flagship-verified: 111 unit, 30 e2e, build green).

## 0. Design read

Reading this as: a developer portfolio for AI-startup founders and hiring managers who decide in about 40 seconds. The language is editorial colour-blocking on a warm dark base, carried by one serif display face, a mono system voice and three card colours. The stack stays as it is: Tailwind v4 tokens, GSAP ScrollTrigger for scroll work, and Motion for React state.

Dials (taste skill, developer portfolio preset raised for the Awwwards ask): `DESIGN_VARIANCE 7`, `MOTION_INTENSITY 7`, `VISUAL_DENSITY 4`.

## 3. Motion plan (additions only, follows MOTION-PLAN.md and the V3.2 relaxations)

1. **Hero load sequence (CSS only, first paint):** the name lines wipe up through a clip-path mask (0 and 120ms), then the H1 words (existing), then the lead and CTAs (700 and 850ms), then the sheet edges draw (existing CSS). Reduced motion shows everything at once.
2. **Work row hover fill:** a `::before` layer at `clip-path: inset(100% 0 0 0)` moves to `inset(0)` over 450ms `cubic-bezier(.22,1,.36,1)`. Pointer devices only. Focus-visible gets the same fill.
3. **Metric cells:** the existing reveal wipe, with no new motion.
4. **Contact block:** the section's clip-path opens from the bottom as it enters (reuses `[data-reveal]`).
5. No new ScrollTriggers beyond the existing batch. Budget: the motion chunk stays at or below 60 KB gzipped.

**Eng amendments (these override anything above that conflicts with them):**
- `.tone-ink` sets CSS variables only: no `color`, and no `--color-signal` override. Text colour comes from `text-ink` in the markup. Inside a toned block, accent uses must be written as `text-ink`, not `text-signal`.
- The Contact background is `bg-card-1` (#FFE899), never `bg-signal`. The Copy hover is `hover:bg-signal-ink hover:text-card-1`.
- No class names built at runtime. A new `src/lib/cards.ts` exports `CARD_BG = ['bg-card-1','bg-card-2','bg-card-3'] as const`, `cardIndex(i) = i % 3`, `cardBg(i)` and `cardVar(i)` (returns `var(--color-card-N)`). Work, Proof and ProjectPage use it. A unit test (`scripts/cards.test.mts`, flagship-written) pins the rule.
- The Work fill CSS lives in one `.work-row` block in `index.css`:
  - `.work-row > [data-work-fill]` is clipped at rest.
  - `@media (hover:hover) { .work-row:hover > [data-work-fill] {inset 0} .work-row:hover .work-text {color:#14110F} }`.
  - `.work-row:focus-visible` gets the same two rules.
  - Reduced motion: no transition.
  - Every visible text span in the row has `work-text`. The row is `work-row group`.
  - No `group-hover:[@media…]` utilities.
- `.line-up` under reduced motion: `animation:none; transform:none`.
- Contact: put `data-reveal` on an inner wrapper div, never on the section. The display H2 does not get `data-split`. Use `leading-[1.05] pb-[0.1em]`.
- Hydration flag: `App.tsx` adds `useEffect(() => { document.documentElement.dataset.hydrated = '1' }, [])`. The e2e tests wait for it.
- Do not remove or rename: `word-mask`, `data-hero-sheet`, `data-work-preview`, `data-testid="work-row"`, `data-reveal`, `data-split` (other sections), the `scroll-progress` class, or `section[id]` ids.

**Baseline bugs the e2e suite found (fix in this pass):**
- B1 (not a bug): the 404 is `/_vercel/insights/script.js`, which Vercel injects only in production. The test ignores `/_vercel/`.
- B2 (real, fix as chunk C0):
  - Symptom: with reduced motion on, the `FlowGraph` groups, edges and nodes stay at `opacity:0` forever.
  - Root cause: the SSR prerender has `useReducedMotion()` false, so it emits `opacity:0`. The client's first render already has it true and wants `opacity:1`. React 19 does not patch attribute mismatches when it hydrates, so the DOM keeps `0`. No later render changes the value, so it never updates.
  - Fix: in `FlowGraph.tsx`, gate `reduced` behind a mount flag, `const [mounted,setMounted]=useState(false); useEffect(()=>setMounted(true),[]); const reduced = mounted && (useReducedMotion() ?? false)`. Call the hook unconditionally. The first client render then matches the SSR output, and the post-mount render flips the opacity.
